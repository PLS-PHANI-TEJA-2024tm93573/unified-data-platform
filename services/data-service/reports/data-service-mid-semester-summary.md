# Data Service: Mid-Semester Report Summary

## 1. Service Overview

The Data Service is responsible for receiving, storing, and retrieving time-series measurements generated by industrial assets. It works with the Asset Model Service, which remains the authoritative source for assets, asset variables, data types, and units.

The service is implemented using NestJS, TypeScript, TypeORM, PostgreSQL, TimescaleDB, NATS, and gRPC.

## 2. Primary Features

### 2.1 Measurement Ingestion

The service subscribes to the NATS subject `industrial.measurements` and receives messages in the following format:

```json
{
  "variable_id": "asset-variable-uuid",
  "timestamp": "2026-09-22T10:00:00Z",
  "value": 42.5
}
```

The `MeasurementConsumer` validates the JSON structure, Asset Variable UUID, timestamp, Asset Variable existence, and compatibility between the value and its data type.

### 2.2 Typed Measurement Storage

Measurements are stored using typed nullable columns:

- `numeric_value` for floating-point and integer values
- `boolean_value` for Boolean values
- `text_value` for string values

This avoids storing all telemetry as unvalidated generic JSON.

### 2.3 Time-Series Persistence

The `measurements` table is implemented as a TimescaleDB hypertable. It is indexed by:

```text
(variable_id, timestamp DESC)
```

This supports efficient historical and latest-value queries.

### 2.4 Asset Model Metadata Synchronization

At startup, the service retrieves the complete asset hierarchy from the Asset Model Service through gRPC. The hierarchy is flattened into the local `data_service_variables` cache, which stores:

- Asset Variable ID
- Asset ID
- Variable name
- Data type
- Unit
- Synchronization timestamp

The synchronization process performs transactional upserts and removes stale metadata.

### 2.5 Historical Measurement Queries

The service provides:

```text
GET /measurements
```

This endpoint retrieves measurements for an Asset Variable within a time range using `asset_variable_id`, `from`, `to`, and an optional `limit`.

### 2.6 Latest Measurement Queries

The service provides:

```text
GET /measurements/:assetVariableId/latest
```

This endpoint returns the latest available measurement for an Asset Variable.

### 2.7 Value Normalization

The service converts database-specific typed columns into a common API representation:

```json
{
  "timestamp": "2026-09-22T10:00:00.000Z",
  "value": 42.5
}
```

Database-specific value columns are not exposed to API consumers.

### 2.8 Data Integrity and Error Handling

The service rejects malformed messages, invalid UUIDs, invalid timestamps, unknown Asset Variables, data-type mismatches, and invalid time ranges. Rejected messages are logged without terminating the service.

### 2.9 Migration-Based Database Management

Database changes are managed using explicit TypeORM migrations. Automatic schema synchronization is disabled:

```text
synchronize: false
```

This supports controlled and repeatable database evolution.

### 3.5 Database Design

Describe the following tables.

#### `measurements`

- Composite primary key: `(variable_id, timestamp)`
- Typed nullable value columns
- TimescaleDB hypertable
- Time-series query index

#### `data_service_variables`

- Primary key: `asset_variable_id`
- Cached asset and variable metadata
- No cross-service foreign key
- Synchronization timestamp

Also document column mappings, indexes, migration order, rollback behavior, `synchronize: false`, and data retention considerations.

### 3.10 Validation and Error-Handling Matrix

| Condition | Validation Owner | Result |
| --- | --- | --- |
| Malformed JSON | `MeasurementConsumer` | Message rejected |
| Invalid UUID | `MeasurementConsumer` | Message rejected |
| Invalid timestamp | `MeasurementConsumer` | Message rejected |
| Unknown Asset Variable | Consumer or query service | Rejection or HTTP 404 |
| Data-type mismatch | `MeasurementConsumer` | Message rejected |
| Invalid time range | `MeasurementsService` | HTTP 400 |
| No latest measurement | `MeasurementsService` | HTTP 404 |
| Duplicate measurement key | Database | Insert failure |
| gRPC synchronization failure | `AssetModelSyncService` | Startup failure |

### 3.13 Scope and Limitations

The current Data Service does not yet include:

- Aggregation queries
- Multi-variable queries
- Pagination
- Anomaly detection
- Dashboard functionality
- Asset Model change notifications
- PLC or industrial protocol connectors
- Complete infrastructure-level integration testing
