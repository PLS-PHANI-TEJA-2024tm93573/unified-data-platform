# Simulation model

The pseudo-random generator is a 32-bit seeded linear congruential generator. Seed and tick settings are configurable and repeat a run when the same sequence of lifecycle actions is used. Simulation time advances in UTC by `tickIntervalMs × speedMultiplier`; it freezes while paused.

| Asset | Implemented behavior |
|---|---|
| Mixer_01 | RUNNING with ingredient weight, mixing speed, batch count, cycle duration, and batch ID. |
| Boiler_01 | HEATING with bounded, gradual temperature/pressure curves, target values, cycles, and batch ID. |
| Boiler_02 | Available/idle spare boiler with ambient measurements. |
| Boiler_Hub | Derived availability/active count; no machine OEE. |
| Pump_0 | RUNNING flow, cumulative transferred volume, cycle count, batch ID. |
| Packager | Fractional accumulator converts variable bottles/minute into integer bottles. Per-unit quality decisions conserve exact total/good/rejected counts. Fault probability, recovery, and rare jam event are simulated. |
| Station01 | Derived line status and active equipment count; no production counters. |
| ProductionLine01 | Mirrors final Packager good/rejected/total counts and line state. |

Routing uses `batch-N` identifiers derived from mixer batch progress and selects Boiler_01. This is a simplified demo correlation, not material genealogy. Machine states are emitted only on transitions. Fault intervals close on recovery or service shutdown. Rare packager jams stop production for five simulated seconds and produce paired downtime start/end events. Planned breaks occur at the end of each configured shift; production idles during the break, which is excluded from planned production time. The fault model is currently a per-tick probability with automatic recovery, not a calendar fault schedule. Setup/maintenance states are reserved in the API domain but are not generated by the current model.

Counters are cumulative per run; reset clears them only after stopping. Quality is decided only for produced bottles. `known-oee-demo` fixes seed 7, ideal rate 60, no speed reduction, reject probability 0, fault probability 0, and jam probability 0; it gives reproducible output under the same tick count and run sequence.
